## Problem

The data behind the site improved but the view did not: today it is a five-tab console that ranks topics, republishes person handles and third-party post text, and gives no plain answer to "what is real in AI today". S1 turns it into dehype, a daily briefing that says what happened in the last 24h, what each story's evidence is, and who has confirmed what, in English and Portuguese, on a record anyone can verify. It matters because the owner is its first daily user (R3-2) and because every later pillar (verdict policy, indicators, awareness map, channels, governance) lands on what S1 publishes.

## Approach

The pipeline stays the data floor. `pulse.py` (standard-library Python) gains the evidence records, the Top 10 cut, the gauge values and the network rules of group A, and writes `briefing.json` beside `pulse.json`. `hype_build.py` applies the same rules to the dossier. Its input, `hype/hype_research.json`, is gitignored and absent outside a research pass, so no CI run can rebuild `web/hype.json`. `hype_build.py` therefore also gets an idempotent `--scrub web/hype.json` mode that applies the group-A rules to the committed output itself. The wish runs it once and commits the result; from then on each refresh runs it again after the deleted-post recheck, so a removal-listed or deleted dossier post leaves the committed file (row 7), and every later research pass runs the full build through the same rule code and the same two removal lists. Then one Node step composes the outputs with the qualified Cordis API: a feed plugin writes the four feed files and a frontend plugin writes the per-language data and string tables. The pages are static HTML and JS that read those files, so D5's "no build" still holds for the pages themselves. The verdict file is a reviewed JSON file in git: the owner upgrades a row by PR and the merge is the confirm. Each run writes a daily ledger to Pages and a full input manifest to a dated Release, attests the manifest with Sigstore and stamps it with OpenTimestamps. `scripts/check_page.mjs`, which already guards `pulse.json` against `x_handles`, grows into the single public-file gate that every rule above fails in CI. Because the gate then reads `web/i18n/`, `web/checks/`, `web/ledger/`, the new pages, the policy and method copies and the four feeds, `ci.yml`'s search-index job copies the whole tree (`cp -R web "$RUNNER_TEMP/"` in place of `mkdir -p "$RUNNER_TEMP/web" && cp web/*.json web/index.html "$RUNNER_TEMP/web/"`), so the gate runs complete on its scratch copy too (reviewer MEDIUM-1).

Alternatives considered:
- Plain build-time modules now, Cordis later: lost to R5-1, which picked the qualified Cordis API now as a one-shot build.
- Waiting for the Cordis gate (the R4-3 answer): reopened by R5-1. The gate has no date and concerns a running DSH application.
- Keeping one `web/index.html`: R1-4 reopened D5 for several static pages, and the fold (R6-3) needs a page per console tab.
- A model or a heuristic that proposes labels: R4-1 found no computed field can tell whether a claim is true, and the repository has no model code. The free hosted route (GitHub Models) was retired.
- Ranking the Top 10 by heat alone: R6-1. On the 2026-10-16 snapshot it held no story first seen in the last 24h.
- Machine-translated headlines (`opus-mt-en-ROMANCE`): R8-1 keeps headlines as posted. No source's terms except arXiv grant translation.
- An Ethereum attestation or IPFS: paid. R1-3 picked the no-fee stack with a Bitcoin anchor.
- Hashed handles, or `@user` Mastodon links: R3-3 removed handles, and R8-2 picked the handle-free link or a count.

## Simplicity Case

- **Simplest complete design:** extend the existing pipeline and page guard, add one composition step and static pages, and keep every record in git, Pages or a dated Release. No new service, database or account.
- **Added machinery:** the Cordis step (R5-1 asks for it). The Mastodon render check and its cache: R8-2 links a post only once it is shown to render, and the cache keeps the check inside the run margin. The detector and lists for X figures and dispositions: R8-3 and R3-3 reach prose and free-text fields that no field rule can catch. The SHA256-keyed Portuguese dossier file: R8-1 requires that a changed English text fall back to the notice. The manifest, attestation and timestamp: R1-3 and R2-3. Each of the following has a current need named in a row or a DRAFT condition:
  - The bot-written alias file and the per-day story-id archive: C32, because a confirmed verdict row must stay valid after its story's id moves or the story leaves the 7-day window.
  - `removals.json`: C34, because a removal request must reach the daily rebuild, and only an owner-reviewed list records which requests were accepted.
  - The deleted-post recheck by id: C34, because the search and timeline fetchers never report a deletion, so without it a deleted post stays in the outputs for up to `RETAIN_DAYS` (45) days.
  - The OpenTimestamps upgrade loop: C38, because a pending proof must become anchored without editing earlier ledger entries.
  - The corrections base-commit comparison in `ci.yml`: C40 and C11, because "appended, never edited over" needs a check against the previous version, which the file alone cannot show.
  - `hype_build.py --scrub`: no CI run can rebuild `web/hype.json`, because its research input is gitignored, so the committed output is cleaned in place, once for the group-A rules and then on each refresh for C34's removals.
  - `web/checks/dossier-gone.json`: C34, because dossier posts are reloaded from `web/hype.json` each run and never sit in the history DB, so a deleted dossier post needs its own record, kept as hashes so the file publishes no id of a deleted post.
  - The separate attestation job: C42, least privilege, so no `id-token` or attestation token sits beside `npm ci` and pip code.
- **Deferred until measured:** re-fitting the cron after 7-10 scheduled runs, because no scheduled run has fired yet and the Cordis step's time is unmeasured. Language detection for `lang` stays out (source metadata or `und`) unless untagged headlines prove common. Automated dossier refresh waits until the research pass has a committed input.
- **Complexity removed:** no server, login, analytics or tenant model. No translation model. No pipeline label proposals, so there is no label-quality failure mode. No trend maths before 14 days. No hashed-handle scheme. No Reddit pointers to delete later from an anchored file.
